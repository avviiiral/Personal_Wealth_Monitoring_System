# Mutual Fund Masterdata — Source Map

**Checked on:** 23 November 2026  
**Scope:** India-domiciled mutual-fund schemes across AMCs, not limited to schemes held by a PWMS family.  
**Authority order:** AMFI / SEBI and official exchange data first; official AMC disclosures where the primary industry source is not scheme-level; calculated values only from identified source series; IndianAPI only as optional enrichment under the existing PWMS request budget.

This is a source inventory, not a claim that every field is present for every scheme. A source being publicly viewable does not automatically grant a right to crawl it, bulk-download it, or republish its contents. The automation column is deliberately conservative.

## Important interpretation rules

1. **Do not mix AUM types.** AMFI's scheme-wise report is quarterly Average AUM (AAUM), reported in ₹ lakh. It is not month-end AUM. Store it as `QUARTERLY_AVG`. Store a reported month-end net-assets figure as `MONTH_END` only when the AMC source explicitly labels that figure as at the portfolio/factsheet date. If a factsheet says average AUM for the month, it is not a month-end value; do not silently relabel it.
2. **Portfolio dates are disclosure dates, not download dates.** Use the stated portfolio-as-of date. Keep `fetched_at` separately. The SEBI Master Circular dated 20-Mar-2026 (para 6.1.1) specifies monthly portfolio disclosure as of the last day of the month within 10 calendar days, and debt portfolio/yield disclosure on a fortnightly basis within 5 calendar days.
3. **Riskometer dates are monthly.** SEBI's current Master Circular states riskometers are evaluated monthly and published with the portfolio disclosure within 10 calendar days after month-end. Store the scheme riskometer and its primary benchmark riskometer as separate fields.
4. **TER is a daily, plan-specific field.** Preserve the publication/effective date and the displayed cost component. Do not combine Base Expense Ratio with brokerage/transaction/statutory-cost components unless the field definition explicitly requires the combined figure.
5. **Offer-document fields are versioned.** Exit load, minimum investments, inception/allotment date, fund managers and benchmark name should come from the current SID/KIM, scheme summary, and later addenda. Preserve the source document and effective date; a new document must not erase the prior history.
6. **Debt factsheet metrics are not guaranteed to be present in every factsheet.** AMFI Best Practices Guideline Circular 88/2020 calls for separate Macaulay Duration, Modified Duration, Average Maturity and YTM disclosures in monthly factsheets, but the actual available file must be checked scheme by scheme. Do not calculate or interpolate a missing scheme-level metric from the category name.
7. **Equity ratios need the AMC definition.** P/E, P/B, dividend yield and portfolio turnover are not uniformly present in every downloadable factsheet. Store only disclosed scheme-level values with their as-of date and methodology. Do not substitute index ratios.
8. **Ratings are instrument-level evidence.** A rating split is calculated only from the rating printed for each holding in the dated AMC disclosure. Preserve agency, symbol, outlook/watch if supplied, and rating date. Do not infer a missing rating from issuer names or scrape paid rating databases.
9. **Calculated ratios need aligned source series.** Scheme returns and risk ratios use scheme NAV; benchmark-relative ratios use the scheme's declared primary benchmark TRI, aligned on the same dates. A price index is not a TRI. Missing or insufficient histories remain null with a quality flag.
10. **Match holdings by ISIN first.** Use exact normalized name only as a fallback where the source has no usable ISIN and the match is unique. Log unmatched/ambiguous rows; never fuzzy-guess.
11. **Every persisted value needs lineage.** The planned masterdata tables should record `source`, `source_url`, `as_of_date`, `fetched_at`, and field-level lineage for every populated value. A single record-level source is not enough when fields come from different documents.
12. **Keep raw provider files out of Git.** The planned raw download location is `backend/data/mf_raw/<source>/<date>/`; it must be git-ignored before any collector writes files there. Store only a bounded raw-file path/reference in the source-run log, not the downloaded report in source control.

Re-check the page in a normal browser before implementing a collector against its download controls.
- **BSE:** the official BSE market-data portal resolved and describes a registration / plan / agreement / payment process. The legacy public index archive URL returned HTTP 403 in this check. Treat BSE historical TRI as a licensed-source dependency until BSE provides a suitable feed and permission.
- **Automation permission:** no blanket right to crawl or bulk-republish AMFI/AMC/NSE HTML or download links was established in this review. Public availability and SEBI disclosure obligations are not the same as a crawler/API licence. Before each collector is implemented, review the source's current Terms of Use and `robots.txt`, confirm any licence requirement, use an honest User-Agent, throttle to no more than one request per second per host, and cache raw responses. If terms are silent or ambiguous, keep the source adapter manual / `--from-file` until permission is resolved.

## Existing PWMS implementation reviewed on the base branch

- `AMFIMasterScheme`, `AMFIMasterNAV`, and `AMFISchemeAAUM` are global AMFI scheme/NAV/quarterly-AAUM models in `backend/mutual_funds/models.py`.
- The quarterly AAUM importer is `backend/mutual_funds/management/commands/import_amfi_scheme_aaum.py`; it already has `--dry-run` and stores rupee-crore values after converting AMFI rupee-lakh figures.
- `compute_fund_performance_metrics()`, AMFI universe ingestion and the existing MFapi NAV cache live in `backend/mutual_funds/services/sebi_mf_analytics.py`.
- `OfficialMutualFundUnderlyingService` parses official AMC portfolio documents, but the existing `MutualFundUnderlying` FK targets the family-scoped `MutualFundScheme`. It cannot serve as the market-wide holdings table; the planned global holdings table must FK to `AMFIMasterScheme`.
- The existing optional IndianAPI client and persistent monthly request reservation are in `backend/watchlist/services/indianapi.py`. It clamps PWMS dispatch to at most 400 requests per calendar month; the new pipeline must not add a per-scheme request loop or bypass that ledger.
- `backend/config/settings.py` uses Django's configured database backend and the existing settings style; the masterdata work should continue to support SQLite and PostgreSQL without vendor-specific SQL.
- No `AGENTS.md` was found at the repository root or the checked `.agents/`, `backend/`, `backend/mutual_funds/`, `backend/mutual_funds/services/`, or `docs/` paths on the requested base branch.

## Deliberately unresolved before collector implementation

- Whether AMFI's interactive TER and portfolio pages expose a stable, documented export endpoint suitable for scheduled automation. The collector should prefer official downloadable files; do not hard-code an undocumented internal API without validating its stability and terms.
- Whether AMFI's current monthly factsheets consistently expose a scheme-level month-end net-assets figure distinct from average AUM. Use AMC-specific adapters and nulls rather than assuming one common field.
- BSE historical TRI access requires confirmation of the correct product/feed and a data-use agreement; the publicly accessible BSE page checked here is a market-data sales portal.
- Free, machine-readable, bulk instrument-rating history was not identified. The initial credit-rating source should therefore be the rating printed in each AMC's official dated portfolio disclosure.
- P/E, P/B, and dividend-yield fields are not uniformly present across all scheme factsheets. They remain null where the AMC does not disclose a scheme-level value; a licensed underlying-security fundamentals feed would require a separate decision.
